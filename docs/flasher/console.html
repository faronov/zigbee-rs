zigbee-rs serial console

A terminal for the hub's USB console in the browser, with Wi-Fi setup. Needs Chrome or Edge on a desktop (Web Serial); Firefox and Safari cannot open serial ports. Back to the web flasher.

This browser has no Web Serial. Use Chrome or Edge (version 89 or later) on Windows, macOS or Linux.

Which port

After tbr-hub (or tbr-bridge) starts, the Thread Border Router board's S3 USB port (USB2) shows two serial ports of the device "Thread BR H2 bridge" (manufacturer zigbee-rs-hub):

  • the second port is the console: macOS cu.usbmodem…3, Linux the higher /dev/ttyACM…, Windows usually the higher COM number;
  • the first port is the bridge to the H2 (bridge mode) or the JSON API (hub mode): not a console.

The page sends an empty line and waits for the console prompt >, so a wrong port is reported. It always opens at 115 200 baud: 1 200 baud on the console port would hand the USB port back to USB-Serial-JTAG (the flasher uses that on purpose). Close other programs on the port first. The ZRHP NCP DevKits speak the binary ZRHP protocol on their port: there is no text console there.

Set up Wi-Fi

    
Stores the credentials on the hub (wifi set), switches it to hub mode if it boots as
      the bridge (mode hub, the S3 reboots and the page reconnects), waits for an address and reads the API
      token. The password is only sent to the device: it is not stored by this page, not kept in the history and masked
      in the terminal and the log.

    

      
      
      
    

    
The console takes printable ASCII only and splits on
      spaces: the SSID must not contain spaces, the password not start or end with one or contain two in a row
      (set such networks later in the hub's web UI). 2.4 GHz networks only (ESP32-S3).
